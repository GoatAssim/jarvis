### 🐞 H.1.1 — Daemons panel bug — ✅ FIXED, rev. 2026-09-27 (`jarvis-h11-daemon-panel-fix.patch`)

  - **Approval summary ✅ IMPLEMENTED IN PATCH:** `job_risk.py` classifies from the **tool list, not prompt text**: power (`power_action`), desktop (`type_text`, `write_on_screen`, `press_key`, `hotkey`, `click`, `click_on_text`, `drag`, `scroll`, `move_mouse`, `focus_window`), files (`delete_path`, `write_file`, `edit_file`, `move_path`, `rename_path`, `copy_path`), shell (`run_shell`, `run_custom_command`, `run_command`, `run_chain`, `dev_agent`, `code_agent`). Stored as `risk` at creation, `approved_kinds` frozen at approval, passed to the run as `JARVIS_JOB_APPROVED_KINDS`. A `tool`/`command` job says "will", an `ask` job "can" (the model picks its tools at run time; the list is every router group that matched before trimming). Shown in the web detail pane; **Approve opens a confirm dialog when anything is flagged** (one click when nothing is). **The dialog was not rendered.**
  - **Unattended directive ✅ IMPLEMENTED IN PATCH:** first line of the per-request prompt tail when `JARVIS_SCHEDULED` is set; interactive prompts and the cached prefix are unchanged. An instruction, not a guarantee — untested against a live model.
  - **Circuit breaker ✅ IMPLEMENTED IN PATCH:** in an unattended run a `retryable: false` result or a policy denial stops it — later calls (the rest of a parallel batch included) do not run, and the tool budget is emptied so the model gets one final call to report in a line. Interactive asks never trip it.
  - **Behaviour to know about:** task steps have no approval step, so they are **not** held to approved kinds (they keep the existing rules); a desktop approval also covers the read-only desktop tools; jobs approved before the change have their kinds derived on each run; there is no way to edit a job's action after creation, so approval cannot be widened by editing the prompt (a future edit feature must re-park the job); approval can under-promise for an `ask` job (an unpredicted tool is denied at run time).
