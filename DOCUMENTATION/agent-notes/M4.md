### AGENTS.md, Minecraft invariants (one paragraph)

`inspect_modpack` and `update_modpack_file` (agent M4) work on a pack file the owner already has. Reading is in memory: only the index file (`modrinth.index.json` / `manifest.json`) is read, through a bounded reader; the `overrides/` entries are listed and never opened; nothing is extracted, run, installed or followed, and no URL in a pack is fetched (only its host is reported, and a host that is not Modrinth's is a warning). The limits are constants in `modhosts/packread.py` (entries, declared sizes, per-entry and whole-archive compression ratio, index size) and a pack that breaks one, or has an unsafe name, a link, a duplicate, an encrypted entry or an unknown `formatVersion`/`manifestVersion`, is refused with the rule's name, never guessed at. The pack's own text is stranger text (clipped, marked). Names are looked up through the adapters only: Modrinth gets SHA-1 hashes, CurseForge gets project ids (and only with the owner's key); `resolve: false` makes no call at all. The update writes ONE new file, `<name>-updated.mrpack|zip`, through `outdir.write_atomic(..., overwrite=False)` and never touches the original; there is no `overwrite` argument anywhere, a taken name gets `-updated-2`. "Newer" is a later publication date for the same Minecraft version and loader (`resolve.pick_file`), never a bigger version number, and an installed file that is as new or newer is `unchanged`. An entry that can't be updated (not_found, ambiguous, blocked, no_compatible_file, lookup_failed) stays as it was and is reported; an entry that cannot be carried into a pack Jarvis writes blocks the whole write (`blockers`), so the new pack is never smaller by accident. Overrides are copied zip to zip, unchanged, with their CRC re-checked. Both tools refuse a chat guest before reading anything.

### Guide (Minecraft), short

"Open `D:/Packs/MyPack.mrpack` and tell me what's in it" -> `inspect_modpack`. "Make me an updated copy of it" -> `update_modpack_file` (it shows a dry-run report first; the real run asks 'Save outside the downloads library?'). The old pack is never changed; the new file sits next to it as `MyPack-updated.mrpack`. Things it could not update stay in the new pack exactly as they were, and the report lists them with the reason.
